# 01. 需求分析

## 1. 业务需求

本项目要解决用户在旅行决策中的三个核心问题：

1. 去哪里：根据出发地、时间、预算和偏好推荐目的地。
2. 怎么玩：根据攻略知识库生成合理行程。
3. 怎么去：结合铁路、天气、地图工具判断出行可行性。

项目不是单纯信息展示系统，而是一个能理解用户目标、调用外部工具并综合判断的智能体应用。

## 2. 用户故事

### US-001 不知道去哪

作为用户，我希望输入“上海出发，周末两天，预算 800，想看江南古镇”，系统能推荐几个目的地，并说明推荐理由、交通耗时、天气和注意事项。

验收标准：

- 返回至少 2 个候选目的地。
- 每个目的地包含推荐理由、适合人群、预算估计、交通建议和风险提示。
- 至少调用一次攻略检索工具。
- 在条件允许时调用天气或铁路工具。

### US-002 已有目的地，想规划路线

作为用户，我希望输入“南京三天两夜怎么玩”，系统能生成每天的上午、下午、晚上安排。

验收标准：

- 输出分天行程。
- 包含景点、餐饮、交通距离或路线建议。
- 输出攻略来源引用。
- 对天气、闭馆、拥堵等不确定事项进行提示。

### US-003 查询铁路出行

作为用户，我希望输入“明天杭州到南京有哪些高铁”，系统能调用 12306 MCP 返回车次、时间、耗时和席别信息。

验收标准：

- 系统识别出出发地、目的地和日期。
- 调用铁路 MCP 工具。
- 如果 MCP 不可用，返回清晰降级提示和示例数据说明。
- 不提供购票、抢票、登录功能。

### US-004 根据天气调整行程

作为用户，我希望系统能判断“这个周末苏州下雨还适合去吗”。

验收标准：

- 调用天气工具。
- 结合攻略库判断室内、室外景点比例。
- 给出原计划、雨天替代方案和风险提示。

### US-005 添加攻略

作为用户，我希望粘贴一段攻略，系统自动识别城市、景点、美食、预算、适合季节，并把它加入知识库。

验收标准：

- 后端保存原始文本。
- 大模型抽取结构化字段。
- 文本被切片并写入向量库。
- 新攻略能被后续检索命中。

## 3. 功能需求

| 编号 | 功能 | 优先级 | 说明 |
| --- | --- | --- | --- |
| FR-001 | 智能对话 | P0 | 用户通过聊天方式提问和追问 |
| FR-002 | 攻略检索 | P0 | 从攻略知识库检索相关内容 |
| FR-003 | 个性化推荐 | P0 | 根据出发地、天数、预算、偏好推荐目的地 |
| FR-004 | 行程规划 | P0 | 生成分天行程和路线建议 |
| FR-005 | 12306 MCP 查询 | P0 | 查询铁路车次和余票相关信息 |
| FR-006 | 天气查询 | P0 | 查询目的地实时或预报天气 |
| FR-007 | 地图查询 | P0 | 查询地点、POI、路线距离 |
| FR-008 | 攻略添加 | P0 | 支持用户添加攻略文本或链接 |
| FR-009 | 工具调用日志 | P1 | 记录智能体调用了哪些工具 |
| FR-010 | 会话历史 | P1 | 保存用户和助手消息 |
| FR-011 | 来源引用 | P1 | 输出攻略依据和工具数据来源 |
| FR-012 | 演示模式 | P1 | 外部接口失败时可使用缓存或 Mock 数据 |
| FR-013 | 用户偏好 | P2 | 保存预算、旅行风格、常用出发地 |
| FR-014 | 行程导出 | P2 | 支持导出 Markdown 或复制行程 |

## 4. 非功能需求

| 编号 | 类型 | 要求 |
| --- | --- | --- |
| NFR-001 | 稳定性 | 外部接口失败不能导致后端崩溃 |
| NFR-002 | 性能 | 普通问答首包响应目标小于 5 秒，完整回答目标小于 20 秒 |
| NFR-003 | 可维护性 | 后端服务、智能体、工具、数据库分层清晰 |
| NFR-004 | 可配置性 | API Key、模型名、接口地址全部通过 `.env` 配置 |
| NFR-005 | 可演示性 | 提供 `start.bat`，可以一键启动 |
| NFR-006 | 可解释性 | 保存工具调用记录，前端可展示工具链 |
| NFR-007 | 安全性 | 不在代码中提交真实密钥，不处理购票和支付 |
| NFR-008 | 可测试性 | 核心服务提供单元测试和最小集成测试 |
| NFR-009 | 前端体验 | 界面精致、专业、响应式，避免普通 Demo 感 |
| NFR-010 | 数据质量 | 攻略入库需要清洗、切片、去重和来源记录 |

## 5. 输入输出需求

### 5.1 用户输入类型

- 自然语言咨询
- 推荐条件：出发地、目的地、日期、天数、预算、偏好
- 攻略文本
- 攻略链接
- 追问和纠错

### 5.2 系统输出类型

- 目的地推荐
- 分天行程
- 火车车次表
- 天气风险提示
- 地图路线摘要
- 攻略来源引用
- 工具调用过程
- 攻略添加结果

## 6. 数据需求

| 数据类型 | 来源 | 用途 |
| --- | --- | --- |
| 初始攻略文本 | 微博攻略合集和人工整理 | RAG 知识库 |
| 用户新增攻略 | 前端添加入口 | 知识库增量更新 |
| 车次信息 | ModelScope 12306 MCP | 出行建议 |
| 天气信息 | 高德天气 API | 风险判断 |
| 地点和路线信息 | 高德地图 API | 地图和通勤建议 |
| 会话数据 | 本地 SQLite | 多轮对话和回溯 |
| 工具调用日志 | 后端自动记录 | 可解释性和答辩展示 |

## 7. 约束条件

- 项目需要在普通 Windows 环境可运行。
- 命令行交互不能依赖开发工具启动，本项目采用浏览器前端加 `start.bat`。
- 12306 只做查询，不做登录、购票、抢票。
- 外部接口可能受限，必须设计缓存和降级。
- 大模型输出可能幻觉，必须使用来源引用和工具结果约束。

## 8. 验收用例

| 用例 | 输入 | 期望 |
| --- | --- | --- |
| AC-001 | “上海出发，两天一夜，预算 800，想轻松一点” | 推荐目的地并说明原因 |
| AC-002 | “南京三天两夜怎么玩” | 输出分天行程和攻略来源 |
| AC-003 | “明天杭州到南京有哪些高铁” | 调用 12306 MCP 并返回车次 |
| AC-004 | “苏州周末下雨还适合去吗” | 调用天气并生成雨天方案 |
| AC-005 | 粘贴一段攻略文本 | 自动抽取字段并入库 |
| AC-006 | 再问刚添加攻略里的城市 | 新内容能被检索到 |
