# 12. 项目计划与风险控制

## 1. 开发阶段划分

### 阶段一：文档与架构

目标：

- 完成需求分析。
- 完成技术选型。
- 完成数据库、API、智能体和前端设计。

状态：已完成文档设计。

### 阶段二：工程骨架

目标：

- 创建后端 FastAPI 项目。
- 创建前端 React 项目。
- 创建基础目录。
- 创建 `.env.example`、`.gitignore`、`start.bat`。
- 实现健康检查。

验收：

- `start.bat` 可以启动前后端。
- 浏览器能打开首页。
- `/api/health` 返回成功。

### 阶段三：数据库和攻略库

目标：

- 实现 SQLAlchemy 模型。
- 初始化 SQLite。
- 集成 Chroma。
- 实现攻略添加和检索。

验收：

- 示例攻略可入库。
- 搜索接口可返回攻略 chunk。
- 前端能展示攻略库。

### 阶段四：智能体核心

目标：

- 实现 LangGraph 状态和节点。
- 实现意图识别。
- 实现 RAG 工具。
- 实现工具调用日志。

验收：

- 用户问攻略问题时能检索知识库。
- 工具调用记录能在前端展示。

### 阶段五：外部工具

目标：

- 接入高德天气。
- 接入高德地图。
- 接入 ModelScope 12306 MCP。
- 实现缓存和演示兜底。

验收：

- 天气、地图、铁路工具能独立调用。
- 聊天中能自动触发工具。
- 工具失败时不崩溃。

### 阶段六：前端精修

目标：

- 完成旅行决策驾驶舱。
- 完成聊天、行程、工具洞察、攻略添加。
- 完成响应式布局。
- 完成加载、失败、空状态。

验收：

- 页面视觉专业。
- 移动端不重叠。
- 演示链路顺畅。

### 阶段七：测试和答辩准备

目标：

- 补测试。
- 补 README。
- 准备演示数据。
- 打磨答辩脚本。

验收：

- 所有核心场景可运行。
- 断网或接口失败时有降级。
- 答辩脚本可以按顺序演示。

## 3. 主要风险

### R-001 12306 MCP 不稳定

影响：

- 车次查询演示失败。

应对：

- 提供 MockRailProvider。
- 对 MCP 查询加超时。
- 使用缓存。
- 答辩时提前准备成功缓存。

### R-002 高德 API Key 缺失或超限

影响：

- 天气和地图功能失败。

应对：

- `.env.example` 明确说明。
- 提供演示 Mock。
- 前端显示降级提示。

### R-003 大模型输出幻觉

影响：

- 给出错误车次、天气或路线。

应对：

- 实时信息必须来自工具。
- verifier_node 检查回答。
- 回答中标注来源和不确定性。

### R-004 攻略数据不足

影响：

- 推荐质量不足。

应对：

- 先准备 10 到 12 个核心城市样例。
- 支持用户添加攻略。
- 检索无结果时引导补充。

### R-005 前端做成普通 Demo

影响：

- 项目观感弱。

应对：

- 严格按前端设计规范做驾驶舱。
- 工具结果、行程、来源并列展示。
- 重点打磨首屏。

### R-006 本地环境安装失败

影响：

- 答辩无法启动。

应对：

- 使用 SQLite。
- 使用 Vite。
- 提供 `start.bat`。
- 提前在答辩机器试运行。

## 4. 稳定性优先级

项目开发优先级：

```text
能跑通 > 能稳定演示 > 智能体真实调用 > 前端精致 > 扩展功能
```

注意：

- 不为了扩展功能牺牲核心链路。
- 不在答辩前一天做大重构。
- 每完成一个阶段都保留可运行状态。

## 5. 决策记录

| 决策 | 原因 |
| --- | --- |
| 使用 FastAPI | Python 生态适合 LLM、LangGraph 和 RAG |
| 使用 React | 前端交互复杂，组件化更合适 |
| 使用 SQLite | 本地部署最稳 |
| 使用 Chroma | 向量库轻量，适合课程项目 |
| 使用 LangGraph | 可解释多工具智能体 |
| 使用 12306 MCP | 比直接适配铁路网页接口更专业 |
| 使用高德 | 国内天气、地图和 POI 支持好 |

## 6. 质量门槛

进入最终答辩前必须满足：

- 前后端一键启动。
- 核心 5 个演示问题成功。
- 攻略添加成功。
- 工具失败有降级提示。
- 页面无明显错位。
- README 能指导别人启动。
- 无真实 API Key 泄露。
