# 07. 前端设计规范

## 1. 前端定位

前端不是普通聊天 Demo，而是一个“旅行决策驾驶舱”。

核心目标：

- 让用户一打开页面就能规划旅行。
- 让智能体调用工具的过程可见。
- 让行程、天气、车次、地图和攻略来源并排呈现。
- 视觉上体现专业、精致、高级和个性化。

## 2. 设计方向

风格关键词：

```text
高级旅行杂志感 + 城市交通调度台 + 克制的智能产品质感
```

避免：

- 普通营销首页。
- 单一大聊天框。
- 紫色渐变模板感。
- 满屏圆角卡片堆叠。
- 没有层次的旅游网站风格。

追求：

- 清晰的信息层级。
- 有编辑部气质的排版。
- 有地图和车票语义的细节。
- 精致但不干扰操作的动效。

## 2.1 图片资产方向

前端可以使用图片，但图片必须服务于“中国旅行决策”语境，不使用泛欧美风景或无关装饰图。

后续通过 `imagegen` 生成项目专属资产，建议生成：

- 江南水乡街巷：用于左侧规划面板顶部窄幅视觉。
- 中国高铁车窗：用于铁路洞察或车次推荐区。
- 雨天苏州/南京式街区：用于天气风险和雨天替代方案。
- 中国城市地图与旅行计划桌面：用于工具链或空状态。
- 西南山城或古城旅行氛围：用于目的地推荐卡片。

图片使用原则：

- 不做全屏大 hero，不把应用变成旅游宣传页。
- 图片不作为事实依据，只作为视觉语义和氛围。
- 所有图片不包含文字、水印、Logo、可识别真实人物。
- 图片统一放在 `frontend/public/assets/`。
- 组件中使用 `alt` 文本，保证可访问性。

## 3. 页面结构

```text
┌──────────────────────────────────────────────┐
│ 顶部导航：项目名 / 搜索 / 攻略添加 / 工具状态 │
├───────────────┬────────────────┬─────────────┤
│ 左侧规划面板  │ 中央智能体对话  │ 右侧工具洞察 │
│ 条件输入      │ 回答            │ 天气         │
│ 用户偏好      │ 行程时间轴      │ 车次         │
│ 快捷问题      │ 推荐卡片        │ 地图         │
│ 会话列表      │ 来源引用        │ 工具日志     │
└───────────────┴────────────────┴─────────────┘
```

响应式：

- 桌面端三栏布局。
- 平板端左栏收起为抽屉，右栏变为下方标签。
- 手机端单列布局，保留核心聊天和结果卡片。

## 4. 主页面模块

### 4.1 TopNav

内容：

- 项目名：TripSage Agent
- 状态灯：LLM、MCP、Amap、Vector
- 按钮：添加攻略、知识库、演示模式

设计：

- 高度控制在 64px 左右。
- 使用细边框和紧凑布局。
- 不放大幅 Logo，不做营销口号。

### 4.2 PlannerSidebar

内容：

- 出发城市
- 目的地
- 出行日期
- 天数
- 预算
- 旅行偏好标签
- 同行人
- 信息来源模式：攻略库优先、联网增强、自动判断
- 快捷问题

组件建议：

- 输入框
- 日期选择
- 数字 stepper
- 标签按钮
- 图标按钮
- 小型状态提示
- 分段选择器，用于切换检索模式

### 4.3 ChatWorkspace

内容：

- 用户消息
- 智能体回答
- 工具调用过程
- 追问提示
- 输入框

要求：

- 消息不做普通气泡堆叠，要结合“决策记录”的感觉。
- 助手回答支持 Markdown。
- 长回答分区展示。
- 输入框固定在工作区底部。

### 4.4 ItineraryTimeline

内容：

- Day 1、Day 2、Day 3
- 上午、下午、晚上
- 地点、餐饮、交通、预算
- 天气风险标签

视觉：

- 时间轴左侧使用细线和节点。
- 每天有明确标题。
- 不把每个小项都做成大卡片，保持紧凑专业。

### 4.5 InsightPanel

右侧洞察面板，包含：

- WeatherStrip：天气摘要
- TrainResultTable：车次结果
- MapInsight：路线和距离
- SourceDrawer：攻略引用
- ToolCallTrace：工具调用链

要求：

- 每个区域可折叠。
- 工具失败时展示降级状态。
- 数据必须标注更新时间。

### 4.6 AddGuideModal

内容：

- 标题
- 来源链接
- 攻略正文
- 来源类型
- 自动抽取结果预览

流程：

1. 用户粘贴攻略。
2. 点击“解析”。
3. 后端抽取城市、景点、预算、标签。
4. 用户确认。
5. 写入知识库。

## 5. 视觉系统

### 5.1 色彩

建议使用非模板化配色：

```css
:root {
  --color-ink: #18211f;
  --color-paper: #f7f4ed;
  --color-mist: #dfe8e2;
  --color-jade: #1f7a63;
  --color-rust: #c95f3f;
  --color-rail: #2f4f73;
  --color-sun: #e6b450;
  --color-line: #c9d2ca;
}
```

说明：

- `paper` 提供高级纸感背景。
- `jade` 代表旅行中的自然和地图。
- `rail` 代表铁路工具。
- `rust` 作为重点动作和风险提示。
- 避免全蓝、全紫、全灰。

### 5.2 字体

中文优先使用系统可用且清晰的字体：

```css
font-family: "Microsoft YaHei UI", "Noto Sans SC", "PingFang SC", sans-serif;
```

英文和数字可使用更有调度台气质的字体：

```css
font-family: "DIN Alternate", "Bahnschrift", "Segoe UI", sans-serif;
```

规则：

- 正文 14 到 16px。
- 卡片标题 15 到 18px。
- 页面主标题不超过 28px。
- 不使用负字距。
- 不随视口宽度缩放字体。

### 5.3 间距

建议 token：

```css
--space-1: 4px;
--space-2: 8px;
--space-3: 12px;
--space-4: 16px;
--space-5: 24px;
--space-6: 32px;
```

卡片圆角：

```css
--radius-card: 8px;
--radius-control: 6px;
```

遵守要求：

- 卡片圆角不超过 8px。
- 不做卡片套卡片。
- 页面区块不要都漂浮成卡片。

## 6. 动效规范

动效原则：

- 只强化状态变化，不炫技。
- 页面初次加载可做轻微 stagger。
- 工具调用时使用步骤推进动效。
- 回答生成时使用细线扫描或状态脉冲。

建议：

- Framer Motion 用于面板切换、结果出现。
- CSS transition 用于 hover、focus。
- 禁止过度弹跳。

## 8. 交互状态

必须覆盖：

- loading
- streaming
- empty
- success
- failed
- fallback
- disabled
- focused
- hover
- selected

示例：

```text
天气工具失败：
右侧 WeatherStrip 显示“天气服务暂不可用，已使用缓存数据”，同时标注缓存时间。
```

## 9. 可访问性

要求：

- 按钮必须有可读文本或 aria-label。
- 图标按钮需要 tooltip。
- 颜色不能作为唯一状态表达。
- 输入框 focus 状态明显。
- 表格在小屏幕可横向滚动。
- 文本和背景对比度充足。

## 10. 前端接口约定

前端所有接口通过 `src/lib/api.ts` 管理。

建议：

```ts
const api = axios.create({
  baseURL: import.meta.env.VITE_API_BASE_URL || "http://127.0.0.1:8000/api",
  timeout: 30000,
});
```

所有接口返回统一 `ApiResponse<T>`。

## 11. 页面路由

| 路由 | 页面 |
| --- | --- |
| / | 智能体工作台 |
| /guides | 攻略知识库 |
| /guides/new | 添加攻略 |
| /debug/tools | 工具调试页，答辩可用 |

## 12. 答辩展示重点

前端答辩时要展示：

- 用户自然语言输入。
- 智能体识别出的意图。
- 调用了哪些工具。
- 生成的行程时间轴。
- 天气和铁路结果。
- 攻略来源引用。
- 添加攻略后可被检索。
