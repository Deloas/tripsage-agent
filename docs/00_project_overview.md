# 00. 项目总览

## 1. 项目名称

行迹智策 TripSage Agent

副标题：基于攻略知识库、铁路 MCP、天气和地图工具的旅游攻略智能体。

## 2. 项目背景

传统旅游攻略存在三个问题：

1. 信息分散：攻略散落在微博、笔记、文章和评论中，用户需要自己筛选。
2. 缺少实时性：攻略本身无法感知天气、交通、车次、路线距离等实时因素。
3. 难以个性化：同一个目的地，不同用户的预算、天数、出发城市、旅行偏好差异很大。

本项目通过大模型智能体将“攻略经验”和“实时工具”结合起来，让系统不仅能回答“哪里好玩”，还能进一步判断“我现在适不适合去、怎么去、怎么安排更合理”。

## 3. 项目目标

完成一个具有实际用途的智能旅行规划应用，满足期末项目对“大模型及智能体技术占主要工作量”的要求。

核心目标：

- 支持基于攻略知识库的旅游咨询和推荐。
- 支持按出发地、目的地、预算、天数、偏好生成个性化行程。
- 支持调用 12306 MCP 查询铁路出行信息。
- 支持调用天气接口判断出行风险。
- 支持调用地图接口查询地点、距离和路线。
- 支持用户添加攻略，系统自动抽取结构化信息并更新知识库。
- 提供浏览器前端和一键启动脚本，确保不是只在开发工具中运行。

## 4. 核心用户

| 用户类型 | 主要需求 |
| --- | --- |
| 学生旅行者 | 预算有限，希望快速找到周末或假期目的地 |
| 独自旅行者 | 关注安全、路线简单、住宿和交通便利 |
| 城市短途用户 | 想根据高铁耗时、天气和预算决定去哪 |
| 攻略整理者 | 想把攻略资料沉淀为可检索、可复用的知识库 |
| 答辩老师 | 关注项目创新性、工程完整度、智能体技术含量和演示稳定性 |

## 5. 项目边界

### 5.1 项目包含

- 攻略问答
- 目的地推荐
- 行程规划
- 火车查询
- 天气查询
- 地图地点和路线查询
- 攻略添加
- 会话历史
- 工具调用日志
- 答辩演示流程

### 5.2 项目不包含

- 不做购票、抢票、登录 12306 或验证码处理。
- 不做真实酒店预订或支付。
- 不做金融交易。
- 不做用户敏感个人信息采集。
- 不保证第三方攻略内容完全准确，回答中必须保留来源和不确定性提示。

## 6. 项目创新点

1. 攻略知识与实时工具融合  
   普通 RAG 只能检索攻略，本项目会进一步调用天气、地图和铁路工具，让结果具备实时决策价值。

2. 基于 LangGraph 的多节点智能体  
   通过意图识别、信息补全、工具选择、结果校验等节点体现智能体编排能力。

3. 支持知识库成长  
   用户可以添加攻略，系统自动抽取城市、景点、美食、预算、季节和注意事项，并更新结构化数据库与向量库。

4. 可解释的工具调用链  
   系统记录每次调用了哪些工具、返回了哪些摘要，答辩时可以展示智能体的决策过程。

5. 高质感前端工作台  
   前端不是普通聊天框，而是“旅行决策驾驶舱”，同时展示对话、行程、天气、车次、地图和引用来源。

## 7. MVP 与增强版本

### 7.1 MVP 必须完成

- Web 前端
- FastAPI 后端
- SQLite 数据库
- Chroma 向量库
- 攻略导入和 RAG 问答
- 高德天气查询
- 高德 POI 或路线查询
- 12306 MCP 查询工具
- LangGraph 智能体流程
- 攻略添加
- `start.bat` 一键启动

### 7.2 增强功能

- 用户偏好画像
- 多方案对比
- 行程导出 Markdown
- 工具调用可视化时间线
- 城市推荐评分模型
- PostgreSQL + pgvector 生产级升级方案

## 8. 成功标准

项目成功的判断标准：

- 用户输入自然语言后，系统能判断意图并调用合适工具。
- 回答中包含攻略依据、实时天气、铁路信息或地图信息。
- 添加攻略后，新攻略可以被后续问答检索到。
- 外部接口失败时，系统能返回降级结果，不崩溃。
- 前端界面专业、美观、清晰，能体现项目完成度。
- 答辩时可通过 3 到 5 个典型问题稳定演示。
