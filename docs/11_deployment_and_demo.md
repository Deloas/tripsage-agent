# 11. 部署与答辩演示方案

## 1. 部署目标

项目需要在 Windows 本地稳定运行，用户通过浏览器访问。

要求：

- 不依赖开发工具手动运行。
- 提供 `start.bat` 一键启动。
- 前后端自动启动。
- 外部接口失败时仍能通过演示模式展示核心流程。

## 2. 本地目录目标

最终工程骨架建议：

```text
大模型期末项目/
  README.md
  start.bat
  .gitignore
  docs/
  backend/
  frontend/
  data/
  logs/
  mcp_servers.example.json
```

## 3. 环境要求

后续落骨架时建议：

```text
Python 3.11+
Node.js 20+
Windows 10/11
```

Python 依赖通过：

```text
backend/pyproject.toml
```

前端依赖通过：

```text
frontend/package.json
```

## 4. 环境变量

用户需要复制：

```text
backend/.env.example -> backend/.env
```

并填写：

```text
LLM_API_KEY=
LLM_BASE_URL=
LLM_MODEL=
AMAP_API_KEY=
```

MCP 配置：

```text
mcp_servers.example.json -> mcp_servers.json
```

根据 ModelScope 12306 MCP 页面说明填写真实启动方式或连接方式。

## 5. start.bat 设计

`start.bat` 目标：

1. 检查 Python。
2. 检查 Node。
3. 创建后端虚拟环境。
4. 安装后端依赖。
5. 安装前端依赖。
6. 初始化数据库。
7. 启动 FastAPI。
8. 启动 Vite。
9. 打开浏览器。

答辩时可提供快速模式：

```text
start.bat
```

或者：

```text
start.bat --demo
```

## 6.1 运行前自检

在安装依赖前，可以先运行：

```bash
python preflight.py
```

该脚本不会安装依赖，也不会修改文件，只检查：

- Python 版本
- Node 和 npm 是否存在
- 示例配置文件是否存在
- 8000 和 5173 端口是否空闲

## 6.2 启动后冒烟测试

服务启动后运行：

```bash
cd backend
.venv\Scripts\python.exe -m app.scripts.smoke_test
```

该脚本会验证：

- 后端健康检查
- 工具状态
- 数据库和向量库诊断
- 攻略列表
- 一次真实聊天请求

## 7. 数据初始化

初始化命令后续实现为：

```text
cd backend
python -m app.scripts.init_db
python -m app.scripts.seed_guides
```

初始化结果：

- 创建 SQLite 数据库。
- 创建 Chroma collection。
- 启动后端时自动导入内置初始攻略。
- 启动后端时自动补建本地向量索引。
- 写入演示缓存。

自动导入配置：

```text
AUTO_SEED_GUIDES=true
AUTO_REBUILD_VECTOR_INDEX=true
AUTO_CRAWL_WEIBO_ON_STARTUP=false
```

默认不在启动时采集微博，避免启动速度受网络影响。需要自动联网采集时可手动改为 `true`。

## 8. 演示模式

演示模式开关：

```text
DEMO_MODE=true
```

演示模式用途：

- 外部接口失败时不影响演示。
- MCP 不可用时使用本地铁路样例。
- 高德失败时使用本地天气样例。
- LLM 不可用时至少展示工具结果和错误提示。

前端必须标记：

```text
当前使用演示兜底数据
```

## 9. 答辩演示脚本

### 场景一：目的地推荐

输入：

```text
上海出发，两天一夜，预算800，想轻松一点，去哪比较好？
```

预期展示：

- 智能体识别推荐意图。
- 检索攻略知识库。
- 查询天气。
- 推荐苏州、南京、杭州等候选。
- 显示工具调用链和来源。

### 场景二：行程规划

输入：

```text
南京三天两夜怎么玩？我喜欢历史和美食。
```

预期展示：

- 分天行程。
- 上午、下午、晚上安排。
- 景点和美食。
- 攻略来源。
- 地图路线摘要。

### 场景三：铁路查询

输入：

```text
明天杭州到南京有哪些高铁？
```

预期展示：

- 调用 12306 MCP。
- 显示车次、出发时间、到达时间、耗时。
- 明确说明只提供查询，不提供购票。

### 场景四：天气调整

输入：

```text
这个周末苏州如果下雨，还适合去吗？
```

预期展示：

- 调用天气工具。
- 给出雨天风险。
- 推荐室内或低雨天影响路线。

### 场景五：攻略添加

操作：

1. 点击添加攻略。
2. 粘贴一段苏州攻略。
3. 点击解析。
4. 确认入库。
5. 再问“刚才添加的苏州攻略有什么推荐”。

预期展示：

- 自动抽取城市、景点、美食、标签。
- 写入知识库。
- 新攻略能被检索。

### 场景六：微博公开攻略采集

操作：

1. 点击添加攻略。
2. 点击“采集微博”。
3. 等待采集结果返回。
4. 查看右侧“本地来源”统计。

预期展示：

- 系统显示发现数量、正文入库数量、待处理数量。
- 公开正文成功进入本地攻略库。
- 受限链接以待处理来源保存，不绕过登录或验证码。

## 11. 常见问题回答

### Q1：为什么不用普通 ChatGPT 问答？

普通问答无法保证实时车次、天气和地图信息准确。本项目让大模型调用工具，并基于工具结果回答。

### Q2：为什么用 LangGraph？

旅游规划需要多步骤决策。LangGraph 可以把意图识别、工具调用、规划生成和校验拆成清晰节点，便于控制和展示。

### Q3：12306 接口稳定吗？

项目使用 ModelScope 12306 MCP 做查询工具，同时设计缓存和演示兜底。不做购票和登录，降低风险。

### Q4：攻略数据怎么更新？

用户可以在前端添加攻略，后端自动抽取结构化字段、切片并写入向量库。
