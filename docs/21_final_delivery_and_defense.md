# 21. 最终交付与答辩说明

## 1. 当前项目状态

TripSage 目前已经完成一个可运行、可演示、可继续产品化的旅游攻略智能体主链路，核心能力包括：

- 旅游攻略知识库检索与新增入库
- DeepSeek 大模型规划与对话
- 12306 MCP 车次查询接入
- 高德天气、地理编码、POI、路线规划接入
- 联网搜索增强与本地攻略双模式切换
- 流式输出与结构化决策模块展示
- 行程版本管理、导出、分享
- 用户登录、游客模式、历史中心
- 用户偏好画像、纠偏、审计、时间线撤销

从课程项目标准看，项目已经具备完整的智能体闭环；从产品化角度看，当前版本也已经具备稳定的 MVP 形态。

## 2. 一键交付巡检

项目根目录提供：

```bat
check_all.bat
```

它会依次检查：

- 后端 `pytest`
- 前端 `npm run build`
- 启动本地后端并执行核心烟测
- 登录态历史中心与用户画像全链路烟测
- DeepSeek、高德、联网搜索、12306 MCP 的可选 live 检查

说明：

- 若未配置 `LLM_API_KEY`、`AMAP_API_KEY`，或未开启 `MCP_12306_ALLOW_LIVE=true`，脚本会标记为 `SKIP`，不会误判整个项目失败。
- 巡检日志会写入 `logs/check-all-backend.out.log` 和 `logs/check-all-backend.err.log`。

## 3. 推荐演示顺序

建议答辩时按下面顺序演示：

1. 启动项目：运行 `start.bat`
2. 展示工作台：说明本地攻略、联网搜索、工具状态、历史中心、画像中心
3. 目的地推荐：输入“上海出发，两天一夜，预算 800，想轻松一点”
4. 行程规划：输入“南京三天两夜，喜欢历史和美食”
5. 12306 查询：输入“明天杭州到南京有哪些高铁”
6. 雨天调整：输入“如果苏州周末下雨，还适合去吗”
7. 行程二次优化：修改某一天预算或景点，继续优化
8. 展示历史中心：查看保存的方案、收藏、标签
9. 展示画像中心：展示长期偏好、本次偏好、黑名单、锁定项、纠偏与时间线撤销

## 4. 答辩时可强调的创新点

- 不是普通问答机器人，而是“旅行决策工作台”
- 不只调用大模型，还做了 RAG、本地知识库、联网搜索、天气、地图、铁路工具编排
- 输出不是一段长文本，而是拆成交通建议、风险提醒、预算提示、行程强度等模块
- 用户画像不是静态标签，而是支持行为沉淀、人工纠偏、审计追踪、撤销回滚
- 同时支持游客模式和登录用户模式，兼顾体验与隐私边界

## 5. 答辩常见问题速答

### Q1：为什么这是智能体，而不是普通聊天页面？

因为它会做意图理解、工具路由、RAG 检索、外部接口调用、结果整合和多轮优化，不是单次文本生成。

### Q2：为什么选 LangGraph？

因为旅游规划天然是多步骤、多工具、多状态的问题，LangGraph 便于把链路拆成清晰节点，方便调试、展示和扩展。

### Q3：为什么支持游客模式？

游客模式降低首次使用门槛；登录用户模式再开启历史持久化、偏好画像和长期个性化，产品逻辑更完整。

### Q4：项目稳定性怎么保证？

有本地攻略兜底、规则兜底、接口失败降级、一键巡检、后端测试和烟测脚本，不依赖单一外部接口存活。
