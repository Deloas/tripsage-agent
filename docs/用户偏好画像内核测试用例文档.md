# 用户偏好画像内核测试用例文档

## 1. 文档目标

本测试文档面向当前项目里的新版用户偏好画像内核，用来验证它是否已经具备下面这些产品级能力：

1. 能从自然语言对话中稳定抽取旅行偏好。
2. 能把长期偏好和本次出行偏好明确分层。
3. 能识别负向偏好、回避项和约束条件。
4. 能接收前端行为埋点并把行为转化为画像信号。
5. 能支持用户手工纠偏，而不是只能被动学习。
6. 能查看画像时间线，并支持撤销可逆动作。
7. 能区分游客模式与登录用户模式。
8. 能保证多用户之间的画像、历史和偏好完全隔离。

这份文档不再只是一组静态“理论用例”，而是升级为一份可以直接拿来压测新版画像内核的“提示词驱动测试文档”。

---

## 2. 当前画像内核能力范围

当前项目中的画像内核，重点不再只是“给用户贴几个标签”，而是形成了一套可学习、可分层、可纠偏、可追溯、可撤销的偏好系统。

### 2.1 当前已支持的核心能力

| 能力 | 说明 |
| --- | --- |
| 对话抽取 | 从聊天内容中抽取城市、预算、交通、节奏、兴趣、回避项等偏好 |
| 双层画像 | 同时输出 `long_term_profile` 和 `session_profile` |
| 聚合画像 | 返回合并后的总画像，供规划链路直接使用 |
| 负向偏好 | 支持“不想太赶”“不要早班车”“避开香菜”这类负向信号 |
| 行为学习 | 收藏、分享、打开历史、版本切换、继续优化等行为会写入画像 |
| 人工纠偏 | 支持 `set_common`、`session_only`、`avoid`、`remove_long_term` |
| 时间线追踪 | 支持查看画像形成时间线 |
| 时间线撤销 | 支持撤销最近的可逆画像动作 |
| 游客隔离 | 游客可正常使用规划，但不会沉淀历史和长期画像 |
| 多用户隔离 | 不同登录用户的偏好、历史、行为完全隔离 |

### 2.2 当前重点接口

| 接口 | 用途 |
| --- | --- |
| `GET /api/preference-profile` | 读取当前画像 |
| `GET /api/preference-profile/timeline` | 读取画像时间线 |
| `POST /api/preference-profile/feedback` | 提交人工纠偏 |
| `POST /api/preference-profile/events` | 提交前端行为事件 |
| `POST /api/preference-profile/timeline/undo` | 撤销时间线动作 |

### 2.3 当前重点字段

建议测试时重点观察这些字段，而不是只看自然语言回答是否“像懂你”：

| 字段 | 说明 |
| --- | --- |
| `preferred_cities` | 用户偏好的目的地城市 |
| `budget_range` | 聚合预算区间 |
| `transport_modes` | 交通偏好 |
| `pace_tags` | 节奏偏好 |
| `interest_tags` | 兴趣偏好 |
| `negative_preferences` | 明确避让项 |
| `behavior_signals` | 由行为学习得到的偏好信号 |
| `profile_strength` | 当前画像成熟度 |
| `recommendation_hint` | 画像摘要说明 |
| `long_term_profile` | 长期偏好层 |
| `session_profile` | 本次偏好层 |
| `recent_evidence` | 最近证据链 |

## 3. 测试前准备

### 3.1 建议测试顺序

建议按下面顺序测试，结果最容易判断：

1. 先做登录用户测试。
2. 再做长期偏好 / 本次偏好分层测试。
3. 再做人工纠偏测试。
4. 再做行为学习测试。
5. 再做时间线与撤销测试。
6. 最后做游客模式和多用户隔离测试。

### 3.2 登录用户测试准备

1. 使用一个已登录账号进入系统。
2. 新开一个对话，不要直接沿用历史会话。
3. 每轮测试尽量只围绕一个主题，避免交叉污染。
4. 每完成一组测试后，查看画像页或调用画像接口确认结果。

### 3.3 游客模式测试准备

1. 退出登录。
2. 重新进入系统，确认当前为游客模式。
3. 重新发起新对话。
4. 测试结束后检查：历史是否为空、画像是否为空、是否提示游客不保存偏好。

### 3.4 多用户隔离测试准备

1. 准备用户 A 和用户 B 两个账号。
2. 让两个账号故意形成相反画像。
3. 分别进入画像页与历史页核对。

## 4. 快速冒烟测试提示词

如果你现在只想先快速感受一下新版画像内核，先跑下面这 3 组就够了。

### 冒烟 01：基础偏好提取

```text
我想从上海去杭州玩两天，预算2000左右，不想太赶，优先高铁，喜欢美食和夜景，别安排太多爬山。
```

**重点观察：**

- 是否提取到 `杭州`、`2000左右`、`高铁`、`慢节奏`、`美食`、`夜景`、`少爬山`。
- 是否能在画像里看到负向偏好。

### 冒烟 02：长期偏好和本次偏好分层

第一轮：

```text
我平时旅行更喜欢安静一点、小众一点，不太爱热门打卡。
```

第二轮：

```text
不过这次是我第一次去成都，还是想把最经典的几个景点先看完。
```

**重点观察：**

- 长期层保留“小众、安静”。
- 本次层新增“成都经典打卡”。
- 总画像能做平衡，而不是简单覆盖长期偏好。

### 冒烟 03：手工纠偏和撤销

先输入：

```text
我更喜欢高铁出行，吃的方面比较看重本地特色。
```

然后在画像工作台中做 2 个动作：

1. 对“高铁”点“设为常用偏好”。
2. 对“本地特色”点“仅本次生效”。

接着去时间线里撤销第 2 个动作。

**重点观察：**

- “高铁”应进入长期层。
- “本地特色”应只进入本次层。
- 撤销后，“本地特色”应从本次层移除。

## 5. 单轮偏好提取测试提示词

这一组主要验证系统从单轮自然语言中抽取偏好的能力。

### 用例 01：基础预算 + 节奏 + 交通

```text
我想周末从南京去苏州玩两天，预算1500以内，尽量轻松一点，优先高铁，不想早起赶车。
```

**预期观察点：**

- `budget_range` 有明显偏低或 1500 附近的预算特征。
- `pace_tags` 有轻松、慢节奏。
- `transport_modes` 出现高铁。
- `negative_preferences` 出现“不想早起赶车”。

### 用例 02：拍照偏好 + 氛围偏好

```text
我想去一个拍照很出片的地方，偏文艺、偏松弛感，咖啡店和街区散步比打卡大景点更重要。
```

**预期观察点：**

- `interest_tags` 出现拍照、街区、咖啡店、文艺等信号。
- 不应误识别成高强度景点打卡型用户。

### 用例 03：亲子偏好

```text
这次是带小朋友出行，最好路线简单一点，别走太多路，安排点适合孩子玩的项目。
```

**预期观察点：**

- 画像要能感知“亲子”。
- 节奏应偏轻松。
- 推荐不应以夜生活或高强度爬山为主。

### 用例 04：饮食限制

```text
我不吃香菜，也不太能接受内脏类食物，推荐餐厅的时候帮我避开。
```

**预期观察点：**

- `negative_preferences` 明确出现香菜、内脏类食物。
- 后续推荐餐厅时应回避相关内容。

### 用例 05：住宿偏好

```text
酒店不用太豪华，但一定要干净安静，位置最好方便回酒店休息。
```

**预期观察点：**

- 住宿偏好应该被识别成“干净、安静、交通方便”。
- 不应被误导成高奢酒店强需求。

### 用例 06：强负向约束

```text
我完全不想坐红眼航班，也不想凌晨出发，转车超过一次我也不考虑。
```

**预期观察点：**

- 负向约束权重应足够高。
- 后续方案应主动避开相关交通方式。

### 用例 07：预算与舒适度冲突

```text
我希望越省钱越好，但也别太折腾，最好还能住得舒服一点。
```

**预期观察点：**

- 系统应识别这是“预算敏感 + 舒适度诉求并存”。
- 不应只保留一个维度。

### 用例 08：城市风格偏好

```text
相比特别热门的大城市，我更喜欢有生活感、有本地气息、适合慢慢逛的小城。
```

**预期观察点：**

- 长期风格倾向里应出现小城、生活感、小众、慢逛等信号。

## 6. 长期偏好 / 本次偏好分层测试提示词

这一组是新版画像内核最核心的验证点。重点不是“有没有记住”，而是“有没有分层记住”。

### 用例 09：长期小众，本次经典

第一轮：

```text
我平时旅行更喜欢安静一点、小众一点，不太爱特别热门的地方。
```

第二轮：

```text
但这次是第一次去西安，所以兵马俑、城墙这些经典景点我还是想看。
```

**预期观察点：**

- `long_term_profile` 保留“小众、安静”。
- `session_profile` 出现“西安经典景点优先”。
- 聚合结果能解释“这次允许经典打卡，但长期仍偏小众”。

### 用例 10：长期预算克制，本次纪念日升级

第一轮：

```text
我平时出行预算都比较克制，能省就省一点。
```

第二轮：

```text
不过这次是纪念日，酒店和晚餐可以升级，体验感比省钱更重要。
```

**预期观察点：**

- 长期层保留预算敏感。
- 本次层新增高体验、高预算倾向。
- 推荐结果不应机械地始终压低预算。

### 用例 11：长期高铁，本次自驾

第一轮：

```text
我平时旅游更喜欢高铁，不喜欢机场折腾。
```

第二轮：

```text
这次去川西我愿意自驾，主要想路线更自由一点。
```

**预期观察点：**

- 长期层仍以高铁为主。
- 本次层允许自驾。
- 系统不能把“这次自驾”错误沉淀成长期替代偏好。

### 用例 12：长期慢节奏，本次高密度

第一轮：

```text
我更喜欢一天安排两三个重点，不喜欢赶行程。
```

第二轮：

```text
不过这次假期太短了，还是希望两天内尽量把核心景点都看一遍。
```

**预期观察点：**

- 长期层仍偏慢节奏。
- 本次层出现高密度打卡需求。
- 回答里应主动提示这是节奏冲突，并给出取舍建议。

### 用例 13：长期清淡口味，本次夜市尝鲜

第一轮：

```text
我平时吃得比较清淡，太油太辣的不太行。
```

第二轮：

```text
但这次去长沙我还是想试试当地夜市，哪怕稍微重口一点也可以接受。
```

**预期观察点：**

- 长期层保留清淡口味。
- 本次层允许夜市、重口尝鲜。

## 7. 冲突偏好与权衡能力测试提示词

### 用例 14：不想赶，但想全都玩到

```text
我不想太赶，但两天内又想尽量把这个城市最重要的景点都玩到。
```

**预期观察点：**

- 系统应识别冲突。
- 回答里应出现“二选一”或“优先级建议”，而不是假装两者都能无损满足。

### 用例 15：预算低，但住宿不能差

```text
预算尽量压到2000以内，但酒店我不想住得太差，最好也别离地铁太远。
```

**预期观察点：**

- 系统应说明预算与住宿标准之间的平衡关系。
- 画像不能只记录“低预算”，还要保留“住宿底线”。

### 用例 16：想小众，又怕交通麻烦

```text
我喜欢小众一点的地方，但交通别太复杂，不想为了去一个地方折腾太久。
```

**预期观察点：**

- 小众偏好与低折腾偏好同时存在。
- 推荐目的地时应收敛到“可达性还不错的小众地”。

## 8. 人工纠偏动作测试

这一组用来验证新版画像不只是“自动学习”，而是真正可控。

### 8.1 先喂给系统一组基础偏好

先输入下面这段：

```text
我一般比较喜欢高铁出行，喜欢美食、夜景和散步，不太喜欢太早出发。
```

然后进入画像区域或调试接口，观察系统是否已经识别出：

- 高铁
- 美食
- 夜景
- 散步
- 不太喜欢太早出发

### 8.2 四类纠偏动作测试

#### 动作 A：设为常用偏好 `set_common`

操作建议：

- 对“高铁”执行“设为常用偏好”。

**预期观察点：**

- `long_term_profile.transport_modes` 中出现高铁。
- 时间线里新增一条长期画像增强事件。

#### 动作 B：仅本次生效 `session_only`

先输入：

```text
这次我特别想去看演唱会，行程可以围绕晚场活动来安排。
```

操作建议：

- 对“演唱会 / 晚场活动”执行“仅本次生效”。

**预期观察点：**

- 该偏好进入 `session_profile`。
- 不应写进 `long_term_profile`。

#### 动作 C：不再推荐 `avoid`

先输入：

```text
以后尽量别给我安排红眼航班，也别推荐早班车。
```

操作建议：

- 对“红眼航班”“早班车”执行“不再推荐”。

**预期观察点：**

- `negative_preferences` 增强。
- 后续规划应主动绕开这类交通方案。

#### 动作 D：移出长期偏好 `remove_long_term`

先让系统形成一个长期偏好，例如“夜景”。

然后执行：

- 对“夜景”点“移出长期偏好”。

**预期观察点：**

- `long_term_profile.interest_tags` 中移除夜景。
- 若本次会话仍有夜景需求，可继续保留在 `session_profile`。

## 9. 行为学习测试

这一组验证系统是否真的会从用户行为中学习，而不是只会从聊天文本学习。

### 9.1 行为学习前置提示词

```text
请给我做一份从上海出发去南京的周末慢游计划，预算1800左右，高铁优先，偏美食和历史街区。
```

### 9.2 建议测试的行为动作

在前端依次做下面这些动作：

1. 收藏当前方案。
2. 点继续优化。
3. 切换到新版本。
4. 再回退到旧版本。
5. 打开历史规划中心，再从历史里打开这次会话。
6. 分享方案。

### 9.3 预期观察点

重点看 `behavior_signals` 和时间线中是否出现与以下行为接近的信号：

| 行为 | 对应事件动作 |
| --- | --- |
| 收藏方案 | `favorite_on` |
| 取消收藏 | `favorite_off` |
| 分享方案 | `share_plan` |
| 从历史继续打开 | `history_open` |
| 选择某个版本 | `version_select` |
| 回退版本 | `version_rollback` |
| 继续优化 | `continue_optimize` |

**通过标准：**

- 行为信号能出现在画像中，而不是只写日志不进画像。
- 行为信号能影响后续推荐倾向。
- 时间线能看到行为带来的画像增强痕迹。

## 10. 时间线与撤销测试

这一组是新版画像内核和普通“偏好标签系统”拉开差距的关键测试。

### 10.1 时间线测试步骤

1. 登录用户 A。
2. 新开一个对话。
3. 输入下面这段：

```text
我平时更喜欢高铁和美食，这次还想加一点夜景安排。
```

4. 对“夜景”执行“仅本次生效”。
5. 读取时间线，找到刚才新增的那条事件。

### 10.2 撤销测试步骤

1. 在时间线中撤销刚才那条“仅本次生效”的动作。
2. 再次读取画像。
3. 再次读取时间线。

### 10.3 预期观察点

- 时间线项目带有清晰的事件描述。
- 撤销后返回最新画像与最新时间线。
- 被撤销事件应标记为 `is_undone=true`。
- 被撤销的偏好应从对应层中消失。

## 11. 游客模式测试提示词

这一组验证“游客可正常体验，但不沉淀持久画像”的产品策略是否成立。

### 用例 17：游客基础测试

退出登录后输入：

```text
我喜欢周末高铁去周边城市，不想太赶，喜欢夜景和美食，预算控制在2000左右。
```

**预期观察点：**

- 聊天规划功能正常。
- 画像接口返回空结构或临时结构。
- `recommendation_hint` 中明确提示游客模式不会沉淀长期画像。
- 历史会话列表不应保存这次对话。

### 用例 18：游客禁止画像纠偏

游客模式下尝试进行画像纠偏或时间线撤销。

**预期观察点：**

- 后端应拒绝持久化画像纠偏。
- 不应出现游客长期画像。

## 12. 多用户隔离测试提示词

### 用户 A 提示词

```text
我喜欢小众、安静、预算克制一点的旅行方式，能坐高铁就不坐飞机，节奏不要太赶。
```

### 用户 B 提示词

```text
我更喜欢热门打卡、拍照出片、酒店舒服一点的玩法，预算高一点也没关系。
```

### 预期观察点

- 用户 A 的画像偏向小众、低预算、高铁、慢节奏。
- 用户 B 的画像偏向热门、拍照、舒适、较高预算。
- 两人的历史中心、画像内容、行为信号必须完全隔离。
- 用户 A 不应看到用户 B 的历史方案或画像影响。

## 13. 推荐联动测试提示词

这组测试用来看“画像到底有没有真正驱动推荐”。

### 用例 19：画像变化前后对比

先输入：

```text
我更喜欢安静、小众、适合散步和吃本地馆子的地方。
```

然后让系统规划一次。

再输入：

```text
不过这次同行朋友更喜欢热闹、夜景和拍照打卡，你帮我在不太累的前提下平衡一下。
```

然后再次规划。

**预期观察点：**

- 第二次规划应明显不同于第一次。
- 方案中应出现“平衡安静偏好与同行拍照需求”的策略。
- 画像层应该体现新的本次会话偏好，而不是覆盖掉长期偏好。

### 用例 20：负向偏好联动

先输入：

```text
以后尽量不要给我安排太早出发，也别推荐红眼航班。
```

再让系统生成涉及交通的方案。

**预期观察点：**

- 交通建议应主动避开早班车和红眼航班。
- 如果确实绕不开，回答里要主动说明原因，而不是无视偏好。

## 15. 验收清单

跑完整套测试后，建议按下面清单验收。

| 验收项 | 通过标准 |
| --- | --- |
| 偏好提取 | 能稳定抽取城市、预算、交通、节奏、兴趣、回避项 |
| 长期 / 本次分层 | 本次偏好不会直接污染长期层 |
| 负向偏好 | 回避项能进入画像，并影响推荐 |
| 手工纠偏 | 四种动作都能立即生效 |
| 行为学习 | 收藏、分享、历史打开、版本切换、继续优化都能进入画像 |
| 时间线 | 能读取完整事件时间线 |
| 撤销 | 撤销后画像和时间线同步回滚 |
| 游客模式 | 游客不保存历史、不沉淀长期画像 |
| 多用户隔离 | A 用户和 B 用户画像、历史、行为完全隔离 |
| 推荐联动 | 画像变化后，规划结果出现合理变化 |

## 16. 推荐的测试结论写法

你在项目答辩、验收或自测复盘时，建议这样总结新版画像内核：

1. 它不是简单的偏好标签表，而是一套持续学习的偏好系统。
2. 它不仅识别“用户说了什么”，也会学习“用户实际怎么选”。
3. 它支持长期偏好与本次需求分层，避免临时需求污染长期画像。
4. 它支持人工纠偏、时间线追踪和撤销，因此更适合真实产品使用。
5. 它与游客模式、多用户体系、历史规划中心和版本系统是一体化联动的。
